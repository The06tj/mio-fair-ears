# Mio Fair Ears

**放下标签，听听本来的偏好。**

一个小小的音频对比工具：匹配响度、同步切换两个版本，再进行几轮隐藏身份的偏好试听，最后一起揭晓。

**[打开 Mio Fair Ears](https://the06tj.github.io/mio-fair-ears/)** · [English](README.md)

无需账户，无需上传音频。没有运行时第三方依赖，MIT 开源。

## 开始听

1. 点击「试试示例音频」，或分别拖入两段音频。
2. 按播放，通过 **1 / 2** 或 A / B 按钮切换。两段音频始终使用同一个播放时钟。
3. 保持「匹配响度」开启，按需设置循环起止秒数。
4. 开始盲听：每轮随机分配 A / B，隐藏文件名、波形和响度调整值。
5. 分别听过两版后投票，也可以选「没有明显偏好」。最后查看结果，导出设置、投票和笔记。

示例是一段在本地生成的原创合成器小曲，无外部采样，也不会自动发声。

## 适合做什么

对比已经对齐的两版混音、母带、处理效果或音色。匹配使用共同长度内的综合 LUFS，只调低音量，不添加压缩、限制或均衡。切换采用 12 毫秒淡变。

这是**偏好试听工具**，不是 ABX 辨认测试，也不是经过认证的响度仪。投票不能证明音频客观上更好或差异具有统计显著性。

不同长度的文件以较短的一段为共同范围。工具不会自动对齐录音、消除编解码延迟或去除开头静音；设置循环不会改变响度测量范围。

## 本地运行

需要 Node.js 22 或更新版本，无需安装项目依赖。

```sh
git clone https://github.com/The06tj/mio-fair-ears.git
cd mio-fair-ears
node scripts/serve.mjs
```

打开 `http://127.0.0.1:4173`。也可以用其他静态 HTTP 服务器运行。不要直接双击 `index.html`：浏览器模块和 Worker 需要 HTTP/HTTPS 环境。

```sh
node --test tests/*.test.js
node scripts/build.mjs
```

源码服务器的 `/tests/browser.html` 可运行真实 Web Audio 离线输出验证，不会通过扬声器发声。

## 文件与隐私

- 音频只在当前标签页内处理，不上传，也不保存；仅语言选项会保存在本机。
- 刷新会清空音频和投票。导出的 JSON 包含**文件名和笔记**，分享前请自行查看。
- 网站托管服务仍会收到正常的静态网页访问请求。应用没有统计追踪、外部字体或音频网络请求。
- 支持单声道与立体声，0.4 秒至 5 分钟，每文件不超过 80 MB。解码会额外占用内存。
- 单声道先复制成左右双声道，再测量与播放。采样率显示的是解码后的播放采样率。
- WAV 通常最稳妥；其他格式取决于浏览器支持。
- 采样峰值余量不等于真峰值限制，不能修复音频中已有的削波。
